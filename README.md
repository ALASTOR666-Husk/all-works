# 📘 Подробное пошаговое объяснение работы с SQL в Docker

Разберём весь процесс от начала до конца — что, зачем и как работает.

---

## 🎯 Общая цель

Мы создаём **виртуальный сервер базы данных** (MySQL) внутри Docker-контейнера, учимся выполнять основные SQL-операции на двух таблицах с товарами, делаем резервную копию (дамп) и учимся её восстанавливать.

---

## 🔹 ШАГ 1. Подготовка Docker-контейнера

### Зачем это нужно?
Docker позволяет запустить MySQL **изолированно**, не устанавливая его на ваш компьютер. Контейнер — это "виртуальная машина", в которой уже всё настроено.

### Команды подготовки:

```shell
docker ps -a                    # Посмотреть все контейнеры (работающие и остановленные)
docker stop имя_контейнера      # Остановить контейнер, если он мешает
docker container prune          # Удалить все остановленные контейнеры (освободить место)
docker volume prune -a          # Удалить все неиспользуемые тома (данные старых проектов)
```

> ⚠️ **Внимание:** `prune` удаляет данные безвозвратно. Делайте это только если уверены, что старые проекты не нужны.

### Создание рабочей папки и конфиг-файла:

```shell
mkdir products-mysql            # Создаём папку проекта
cd products-mysql               # Заходим в неё
```

Создаём файл `my.cnf` — это **настройки кодировки**. Без них кириллица (русские буквы) в БД будет отображаться как "кракозябры" (`??????`).

```ini
[mysqld]
character-set-server = utf8mb4          # Кодировка сервера
collation-server = utf8mb4_unicode_ci   # Правила сортировки (учитывает регистр, ё и т.д.)

[client]
default-character-set = utf8mb4         # Кодировка клиента

[mysql]
default-character-set = utf8mb4         # Кодировка консоли mysql
```

### Запуск контейнера MySQL:

```bash
docker run --name products-mysql \
  -e MYSQL_ROOT_PASSWORD=123 \           # Пароль root-пользователя
  -e LANG=C.UTF-8 \                      # Языковая локаль
  -v mysql_data:/var/lib/mysql \         # Том для хранения данных БД (чтобы не потерялись при перезапуске)
  -v $(pwd)/my.cnf:/etc/mysql/conf.d/my.cnf \  # Подключаем наш конфиг внутрь контейнера
  -d mysql:latest                        # Запуск в фоновом режиме (-d = detached)
```

**Разбор флагов:**
| Флаг | Значение |
|------|----------|
| `--name` | Имя контейнера (для удобства обращения) |
| `-e` | Переменная окружения (пароль, локаль) |
| `-v` | Volume — привязка папки/тома с хоста в контейнер |
| `-d` | Запуск в фоне (не блокирует терминал) |

### Проверка и вход:

```bash
docker ps                 # Убедиться, что контейнер запущен (статус "Up")
```

```bash
docker exec -it products-mysql mysql --default-character-set=utf8mb4 -uroot -p
```

**Разбор:**
- `docker exec` — выполнить команду **внутри** запущенного контейнера
- `-it` — интерактивный режим с терминалом
- `mysql` — запускаем клиент MySQL
- `--default-character-set=utf8mb4` — принудительно указываем кодировку
- `-uroot` — пользователь root
- `-p` — запросить пароль (вводим `123`)

### Создание базы данных:

```sql
CREATE DATABASE shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE shop;          -- Переключаемся на созданную БД
SHOW DATABASES;    -- Видим список всех БД
```

> 💡 **Аналогия:** `CREATE DATABASE` — это создание нового "шкафа" для данных. `USE` — открытие нужного шкафа. `SHOW DATABASES` — список всех шкафов.

## 🔹 ШАГ 2. Создание таблиц

```sql
CREATE TABLE products1 (
    name  VARCHAR(100) NOT NULL,   -- Строка до 100 символов, обязательное поле
    price INT NOT NULL             -- Целое число, обязательное поле
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**Разбор типов данных:**
| Тип | Описание |
|-----|----------|
| `VARCHAR(100)` | Строка переменной длины, максимум 100 символов |
| `INT` | Целое число (от -2 млрд до +2 млрд) |
| `NOT NULL` | Поле не может быть пустым |

Создаём вторую таблицу `products2` по аналогии.

```sql
SHOW TABLES;   -- Видим список таблиц в текущей БД
```

> 💡 **Аналогия:** Таблица — это "полка" в шкафу. У каждой полки есть название и структура (какие поля).

## 🔹 ШАГ 3. Вставка данных

```sql
INSERT INTO products1 (name, price) VALUES
  ('Дыни', 800),
  ('Клубника', 150),
  ('Яблоки', 120),
  ('Лимоны', 200);
```

**Что происходит:** в таблицу `products1` добавляются 4 строки. Для каждой строки указаны значения полей `name` и `price`.

```sql
SELECT * FROM products1;   -- Показать ВСЕ (*) строки из таблицы
SELECT * FROM products2;
```

**Результат — наши данные в табличном виде.**

## 🔹 ШАГ 4. Основные SQL-операции (реляционная алгебра)

Это **фундамент SQL**. Все сложные запросы строятся из этих базовых операций.

### 1️⃣ Выборка (SELECTION) — фильтр строк

```sql
SELECT * FROM products1 WHERE price > 150;
```

- `WHERE` — условие фильтрации
- Оставляет только строки, где цена **больше 150**
- **Результат:** Дыни (800) и Лимоны (200)

> 💡 **Аналогия:** Вы просите продавца показать товары дороже 150₽. Он отбирает нужные строки из прайса.

---

### 2️⃣ Проекция (PROJECTION) — выбор столбцов

```sql
SELECT name FROM products1;
```

- Вместо `*` (все столбцы) указываем конкретный — `name`
- **Результат:** только названия, без цен

> 💡 **Аналогия:** Вы просите показать только названия товаров, цены вас не интересуют.

---

### 3️⃣ Объединение (UNION) — склейка двух выборок

```sql
SELECT name FROM products1
UNION
SELECT name FROM products2;
```

- Берёт названия из обеих таблиц
- **Автоматически убирает дубликаты** (Дыни и Клубника есть в обеих таблицах, но в результате — по одному разу)
- **Результат:** 6 уникальных названий

**Вариант с дубликатами:**
```sql
SELECT name FROM products1
UNION ALL                    -- ALL сохраняет дубликаты
SELECT name FROM products2;
```

> 💡 **Аналогия:** Сложить два списка покупок и убрать повторяющиеся позиции.

---

### 4️⃣ Разность (EXCEPT) — что есть в первой, но нет во второй

```sql
SELECT name, price FROM products1
EXCEPT
SELECT name, price FROM products2;
```

- Находит строки, которые есть в `products1`, но **отсутствуют** в `products2`
- **Результат:** Яблоки (120) и Лимоны (200) — их нет во второй таблице

> 💡 **Аналогия:** "Что у меня есть в первом магазине, чего нет во втором?"

**Для старых версий MySQL (без EXCEPT):**
```sql
SELECT name, price FROM products1
WHERE (name, price) NOT IN (SELECT name, price FROM products2);
```

---

### 5️⃣ Пересечение (INTERSECT) — что есть в обеих таблицах

```sql
SELECT name, price FROM products1
INTERSECT
SELECT name, price FROM products2;
```

- Находит строки, которые есть **одновременно** в обеих таблицах
- **Результат:** Дыни (800) и Клубника (150)

> 💡 **Аналогия:** "Какие товары есть в обоих магазинах с одинаковой ценой?"

**Для старых версий MySQL:**
```sql
SELECT p1.name, p1.price FROM products1 p1
INNER JOIN products2 p2 ON p1.name = p2.name AND p1.price = p2.price;
```

---

### 6️⃣ Декартово произведение (CROSS JOIN) — все возможные пары

```sql
SELECT t1.name AS name1, t1.price AS price1,
       t2.name AS name2, t2.price AS price2
FROM products1 t1
CROSS JOIN products2 t2;
```

- Каждая строка из первой таблицы **комбинируется** с каждой строкой из второй
- 4 × 4 = **16 строк**
- `t1`, `t2` — **алиасы** (псевдонимы) таблиц, чтобы не писать длинные имена

> 💡 **Аналогия:** Представьте, что вы составляете все возможные combos из двух меню — первое блюдо + второе.

---

### 7️⃣ Соединение (JOIN) — связывание таблиц по условию

```sql
SELECT t1.name, t1.price AS price1, t2.price AS price2
FROM products1 t1
JOIN products2 t2 ON t1.name = t2.name;
```

- `JOIN` (он же `INNER JOIN`) — берёт только строки, где **название совпадает** в обеих таблицах
- `ON t1.name = t2.name` — условие соединения
- **Результат:** Дыни и Клубника с ценами из обеих таблиц

**LEFT JOIN** — все строки из первой + совпадения из второй:
```sql
SELECT t1.name, t1.price AS price1, t2.price AS price2
FROM products1 t1
LEFT JOIN products2 t2 ON t1.name = t2.name;
```
- **Результат:** все 4 товара из `products1`. Если товара нет во второй таблице — вместо цены `NULL` (пусто)

> 💡 **Аналогия:** JOIN — это как VLOOKUP в Excel. Связываем таблицы по общему полю.

---

### 8️⃣ Деление (DIVISION) — не рассматриваем

В реляционной алгебре деление отвечает на вопрос: *"Найти такие A, которые связаны со ВСЕМИ B"*. Для двух простых списков товаров это не имеет смысла — нужна третья таблица связей. Поэтому пропускаем.

## 🔹 ШАГ 5. Создание дампа (резервной копии)

```sql
\q   -- Выходим из MySQL обратно в консоль контейнера
```

```shell
docker exec -e MYSQL_PWD=123 products-mysql mysqldump -uroot shop > dump.sql
```

**Разбор:**
- `docker exec` — команда внутри контейнера
- `-e MYSQL_PWD=123` — передаём пароль через переменную (чтобы не вводили вручную)
- `mysqldump` — утилита экспорта БД в SQL-текст
- `-uroot` — пользователь root
- `shop` — имя БД для экспорта
- `> dump.sql` — перенаправление вывода в файл на хосте

**Что внутри `dump.sql`:**
- `CREATE DATABASE` — создание БД
- `CREATE TABLE` — создание таблиц
- `INSERT INTO` — вставка данных

Это **полный текстовый скрипт**, который можно выполнить на любом MySQL-сервере и получить точную копию БД.

```shell
cat dump.sql   -- Посмотреть содержимое файла
```

## 🔹 ШАГ 6. Уборка (удаление БД)

```shell
docker exec -it products-mysql mysql --default-character-set=utf8mb4 -uroot -p
```

```sql
SHOW DATABASES;    -- Видим БД shop
USE shop;
SHOW TABLES;       -- Видим таблицы

DROP DATABASE shop;   -- УДАЛИТЬ базу данных целиком

SHOW DATABASES;    -- shop больше нет
```

```sql
\q   -- Выход
```

> 💡 **Аналогия:** Мы специально "сломали" БД, чтобы на следующем шаге проверить восстановление из дампа.

## 🔹 ШАГ 7. Восстановление БД из дампа

```shell
docker exec -it products-mysql mysql --default-character-set=utf8mb4 -uroot -p
```

```sql
SHOW DATABASES;   -- shop нет

CREATE DATABASE shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;   -- Создаём пустую БД

SHOW DATABASES;   -- shop появилась
```

```sql
\q   -- Выход из MySQL
```

Теперь **в обычном терминале** (не внутри mysql) импортируем дамп:

```shell
docker exec -i products-mysql mysql -uroot -p123 --force shop < dump.sql
```

**Разбор:**
- `-i` — stdin (принимает данные из файла)
- `-p123` — пароль прямо в команде (без пробела!)
- `--force` — продолжать даже если есть ошибки
- `shop` — имя БД для импорта
- `< dump.sql` — подаём файл на вход

### Проверка восстановления:

```shell
docker exec -it products-mysql mysql --default-character-set=utf8mb4 -uroot -p
```

```sql
SHOW DATABASES;
USE shop;
SHOW TABLES;
SELECT * FROM products1;   -- Данные на месте!
SELECT * FROM products2;   -- И здесь тоже!
```

> ✅ **Вывод:** дамп — это надёжный способ резервного копирования и переноса БД.

## 📋 Итоговая шпаргалка операций

| Операция | SQL-ключевые слова | Суть | Аналогия |
|----------|-------------------|------|----------|
| **Выборка** | `WHERE` | Фильтр строк по условию | "Покажи товары дороже 150" |
| **Проекция** | `SELECT имя_поля` | Выбор столбцов | "Покажи только названия" |
| **Объединение** | `UNION` | Слияние двух выборок (без дублей) | Сложить два списка |
| **Разность** | `EXCEPT` | Что есть в первой, но нет во второй | "Чего нет во втором магазине" |
| **Пересечение** | `INTERSECT` | Что есть в обеих таблицах | "Общие товары" |
| **Декартово произведение** | `CROSS JOIN` | Все возможные пары | Все комбинации |
| **Соединение** | `JOIN ... ON` | Связь таблиц по ключу | VLOOKUP в Excel |
